# FoodScope

FoodScope is a food-composition knowledge graph for **Knowledge Representation and Reasoning (KRR)**. It uses USDA data, reuses FoodOn, validates RDF with SHACL, runs HermiT reasoning, and answers predefined or English questions.

## Setup

Use **Python 3.12** and **Java 21**. From the repository root:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r pipeline/requirements-pipeline.txt
.\.venv\Scripts\python.exe -m pip install --no-deps morph-kgc==2.10.0
.\.venv\Scripts\Activate.ps1
```

The separate Morph-KGC installation follows the course dependency setup. Java must be on `PATH`, or configured through `JAVA_EXE` in `.env`.

For a new checkout, copy `.env.example` to `.env` and add your [Google AI Studio key](https://aistudio.google.com/apikey). Keep an existing `.env` and never commit it.

```dotenv
GOOGLE_API_KEY=your_key_here
LLM_MODEL=gemini-3.5-flash-lite
LLM_MODE=live
```

Only English questions require Gemini. Live requests send the question, schema context and selected examples to the configured model.

## Commands and run options

With the environment activated, run:

```powershell
python run.py
```

This runs the local pipeline and starts the UI. Open **http://127.0.0.1:8000/** after it completes. Keep the terminal open; press **Ctrl+C** to stop the server.

## User interface

Choose a mode from the dropdown:

- **Predefined queries:** view one of 13 saved answers and its SPARQL. Reload results reads the latest `build/answers.json` without rerunning the pipeline.
- **Ask the food graph:** enter an English question. The access layer generates and checks SPARQL, executes it, and displays the answer in the page.

Each mode keeps its own results. The interface also links to the data manifest and ontology.

## Data preparation and outputs

The committed April 2024 USDA Foundation Foods sample contains **358 foods**, **1,499 observations**, **six nutrients** and **28 category definitions**.

The selected nutrients are protein (`1003`), fat (`1004`), carbohydrate (`1005`), fiber (`1079`), sodium (`1093`) and sugars (`2000`). Amounts refer to **100 g edible portion**. Sodium uses mg; the other selected nutrients use g. Missing observations remain unknown.

Preparation follows this sequence:

1. `data/prepare.py` selects records from the original USDA CSVs and writes `foods.csv`, `measurements.csv`, `nutrients.csv` and `categories.csv`.
2. It calls `write_sample()` in `data/build_sample.py`, which writes table definitions and rows into `data/example.sql` using SQLite's `iterdump()`.
3. The pipeline executes that SQL file to create `build/example.sqlite`.

Normal runs use the committed sample and need no download. Original inputs are available from the [April 2024 Foundation Foods archive](https://fdc.nal.usda.gov/fdc-datasets/FoodData_Central_foundation_food_csv_2024-04-18.zip) and [USDA downloads](https://fdc.nal.usda.gov/download-datasets/). Source details and hashes are in [data/manifest.json](data/manifest.json).

Keep `data/` in Git. Original downloads under `data/raw/` are ignored. `build/` can be regenerated by a full run. After manually changing the prepared CSVs, regenerate `data/example.sql` with `data/build_sample.py` before running the pipeline.

## FoodOn reuse

[ontology/ontology.ttl](ontology/ontology.ttl) declares the local Food class as a subclass of FoodOn food product:

```turtle
food:Food rdfs:subClassOf obo:FOODON_00001002 .
```

The ontology imports [foodon-module.ttl](ontology/foodon-module.ttl), resolved locally through [catalog-v001.xml](ontology/catalog-v001.xml). The module contains three asserted ancestor classes: **food product, food material and material entity**. It is a documented extract, not the complete FoodOn ontology.

Our extension adds Food, Category, Nutrient, Observation and CharacterizedFood. A CharacterizedFood is a Food with at least one Observation. Source/version/hash information is in [data/foodon-source.json](data/foodon-source.json); `ontology/fetch_ontologies.py` reproduces the extract from the recorded source.

## Pipeline and tools

| Step | What happens | Tool |
| --- | --- | --- |
| Profile | Inspect the prepared tables and measure constraint evidence. | pandas, ydata-profiling |
| Load | Build the working relational database from `example.sql`. | SQLite |
| Map | Convert SQL rows into RDF using `mapping/mapping.ttl`. | R2RML, Morph-KGC |
| Validate | Check names, references, amounts, uniqueness and completeness. Violations stop the run. | SHACL, pySHACL |
| Reason | Check consistency and infer class membership. | OWL, Owlready2, HermiT |
| Query | Execute the predefined SPARQL queries and save their answers. | SPARQL, Oxigraph |
| Record provenance | Describe source files, processing runs and derivation. | PROV-O |
| Answer English questions | Select examples, generate/check SPARQL, repair up to twice or refuse, then execute. | VoID, Gemini, graph backend |

Local `python run.py` loads the reasoned snapshot into **Oxigraph inside Python**. The Docker stack instead uses **Fuseki**, an RDF server exposing dataset `kr` through an HTTP SPARQL endpoint. Both serve pipeline outputs; source changes require a rebuild and backend refresh.

**PostgreSQL and Ontop** support an optional course comparison. PostgreSQL holds relational source tables, and Ontop translates SPARQL into SQL to expose a virtual graph. They are separate from the default SQLite path. The shared count query returned 358 foods in both views; Ontop does not support our complete CharacterizedFood definition.

## Experiments and results

- **Graph and queries:** 9,359 mapped triples, 350 inferred characterized foods, and 29 foods with recorded protein above 25 g per 100 g.
- **Data quality:** zero SHACL violations and 353 incomplete nutrient-panel warnings. Partial measurements remain in the graph.
- **Entity resolution:** course Jaro-Winkler and weighted scoring compare Foundation/SR Legacy records. Matches remain evaluation results rather than automatic `owl:sameAs` assertions.
- **Classification:** predict fat above 20 g per 100 g using non-fat predictors. Mean category-held-out PR-AUC is 0.392 for logistic regression and 0.440 for GraphSAGE across four scoreable seeds. One seed has no positive test foods; high variation limits conclusions.
- **Link prediction:** mean filtered MRR is 0.339 for TransE and 0.448 for the popularity baseline across three seeds.
- **English-query evaluation:** 11 held-out questions include eight answerable questions and three required refusals. Recorded mean set-of-values F1 is 0.856 with schema alone and 0.954 with examples. The checking/repair setting also scores 0.954; the recorded run needed no repairs. All required refusals were correct.

Reviewed results remain in `model/results/`, `mapping/er/results.json`, `mapping/virtualization-comparison.json` and `report/`. Predictions are separate from the factual answers shown in the UI.
